# 消费者行为研究工作台

双击项目根目录的“启动网页Demo.cmd”，访问 http://127.0.0.1:5173/。页面和研究后端由同一服务提供，仅在本机运行。

首页是研究工作台入口，点击“进入工作台”开始使用；这不是账号登录，当前原型没有账户体系。新用户进入后先看到占据左栏以外全部空间的画像页，可填写每餐预算、口味和饮食限制，分次保存；三项完成后可继续对话并开始预演，未完成时预演入口会引导返回画像页。画像页采用暖调渐变页眉、进度卡和四项底部导航。入口和工作台左栏都预留“政府消费券预演”按钮，当前展示的是研究流程占位，尚未接入政府政策数据。工作台默认接入 LifeSim + DeepSeek 真实模式，采用固定左栏与简洁对话页；左栏可进入画像、决策、评测和消费券面板。发出消息后会立即显示用户消息和处理阶段，最终回复逐步显示；画像提取与意图识别仍需要模型处理时间。多轮交流后确认画像，再生成孪生选择预演；预测先由服务器封存，用户选择或跳过之后才展示模型理由和内部模拟对话。预算和消费券分支使用相同基线快照，后续反馈不倒灌到既有预测。

记忆通过硅基流动 BAAI/bge-m3 生成向量，使用 LifeSim 原生 KVMemory、DenseRetriever 和 Chroma 检索。密钥只由后端读取。模型调用失败会显示错误与重试入口，不自动生成规则回复。

真实会话保存在本机后端；“记住本机会话入口”仅控制浏览器保存入口。可清除对应后端记录或导出JSON。带 session_id 查询参数的本地链接可重开记录，仍遵守预测封存规则。集成测试记录不当作真人样本。

“决策”面板可查找真实周边餐饮店或商店。先在[高德开放平台](https://lbs.amap.com/api/webservice/guide/create-project/get-key)创建应用，新增 **Web 服务** Key，把它填入项目根目录 `config/secrets.local.json` 的 `amap_web_service_key`，然后重启本地服务。无需 Web 端（JS API）Key，也不要把 Key 发到聊天中。进入工作台底部“决策”，选择餐饮店或商店，再点击“使用当前位置查找”；此时浏览器才会请求定位授权。后端将 GPS 坐标转换为高德坐标并查询约 2 公里内的真实地点。坐标只用于本次查询，不写入研究会话或模型记忆。

地点搜索可提供店名、地址和距离；部分餐饮店有人均价，但不保证有营业状态、实时菜单、具体价格、食材或过敏原。对话输入框上方的“定位并推荐真实餐厅”会在用户点击授权后查找地点，并将本次候选交给 DeepSeek 在对话中组织建议；从决策页查询的地点也可供后续对话使用。地点结果仅在本机服务内临时保留30分钟，精确坐标不写入研究会话。真实地点尚未自动纳入 LifeSim/DeepSeek 行为预演；原有4个虚构研究候选仍用于预演，亦无实际交易。形象为CSS立体头像。正式真人研究与批量实证评测待实施。详细协议见项目根目录 docs/consumer_agent_research_protocol.md，接口见 docs/consumer_research_api.md。
