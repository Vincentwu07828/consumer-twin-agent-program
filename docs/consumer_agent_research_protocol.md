# 消费者行为决策 Agent：研究定位与评测方案

更新：2026-10-15。本文是根据用户最新科研目的提出的实验设计，尚未完成数据下载、参与者招募或实证评测。网页为本地交互原型，不能作为模型有效性的证据。

## 1. 研究对象

研究问题：**同一消费者的多轮交流和历史经历，能否使个体孪生在未见消费情境中更准确地预演其选择，以及面对预算、时间和促销变化时的反应？**

真人用户提供偏好、情境、取舍与实际选择。对话助手负责追问、澄清和提供候选。消费者孪生负责在给定信息边界内模拟用户反应或选择。研究者负责配置情境、比较基线、冻结预测、采集留出标签与分析。四者的角色、消息和数据来源必须区分。

“推荐一个适合的方案”与“预测用户实际会怎么选”是两个任务。用户可能为了便利选择价格更高的方案；合理建议不能直接当成真实行为预测。首版保持 LifeSim 原生画像、记忆、用户代理及对话模拟器，在其后增加餐饮消费情境和选择动作，不以点击模型作为必经前置步骤。

## 2. 与参考工作的关系

[LifeSim 论文](https://arxiv.org/html/2603.12152v1)将画像、BDI 认知、时空事件与用户行为组合起来，使用多轮对话评价个性化助手。论文的单场景设置包含 120 个用户、每人 10 个事件，共 1,200 个场景、8 个领域；单场景最多 20 轮。长期设置先给历史，再测试后续场景，测试交互最多 3 轮。应保留原协议复现实验，另行标明餐饮专用的扩展协议。

本地论文原文 `LifeSim/arXiv-2603.12152v1/main.tex` 中的主表与附录 D 包含意图识别、意图完成、自然度、连贯性、偏好恢复、人格对齐。上游 README 另列环境对齐与僵化推理，二者并非与论文主表完全相同的指标集合；不要混称“论文七项标准”。论文也单独验证模拟用户的意图、画像、情境一致性与自然度，并结合人评。

[SocioVerse2](https://socioverse.fudan-disc.com/)提供“人群 P × 环境 E → 行为 B”、纵向事件、干预分支和版本重现的研究组织方式。本项目借鉴其研究工作台与情境分支设计；不把其宏观人群回测结果当成本项目个体孪生的验证结果。

## 3. 平台如何支持多轮研究

1. 初始访谈：在获得授权后询问少量偏好和消费背景；未回答的内容保持未知。每个事实带用户来源、轮次和时间。
2. 情境对话：给出当下情境，通过追问确认预算、距离、口味、等待时间和临时需求。允许拒绝、不消费、自带食物等外部选项。
3. 记忆更新：区分长期偏好与本次状态，例如“平常不吃辣”和“今天不想吃辣”。冲突信息先澄清；不能把 LLM 推断写成用户已确认事实。
4. 决策预演：固定候选及事实、画像版本、截至某轮的记忆；消费者代理输出选择或继续询问/放弃等动作。需要概率时必须设计规范的互斥选择分布并校准；排序分数不能冒充概率。
5. 留出核验：预测保存后才收集用户的独立选择与体验。为了评估未受引导的行为，不先展示孪生预测给参与者；若提前展示，应作为辅助决策/影响研究单独统计。
6. 条件分支：从同一画像和历史快照改变预算、距离或券政策，保持其他条件可比。演示分支只是模型响应；真实干预效果需要随机对照或可信的因果识别。
7. 记录重现：保存全部候选、展示顺序、价格依据、约束、对话、检索证据、动作、模型/提示词/代码版本、随机种子及实际反馈。

网页的三个主要区域：左侧研究与会话；中间用户与 agent 的多轮对话；右侧画像证据、情境分支和评测设计。用户孪生形象只是身份入口，3D 表现不进入科研有效性的主要指标。

## 4. 数据选择：按任务分工

| 数据 | 首阶段用途 | 局限与标签边界 |
|---|---|---|
| [LifeSim / LifeSim-Eval 官方仓库](https://github.com/dfy37/lifesim) | 复现原生用户模拟与助手评测；先抽 dining，再保留跨场景长期记忆实验 | 主要是模拟场景与代理对话。可检验模拟设置下的能力，不能证明真实消费者预测准确。核对实际发布文件、版本与协议后再运行 |
| [MultiWOZ 2.2 官方数据](https://github.com/budzianowski/multiwoz/tree/master/data/MultiWOZ_2.2) | 餐厅域多轮需求提取、状态跟踪、找餐厅与预订任务完成 | 有逐轮状态及价格档、区域、食物等槽位；英国英语任务对话，非中国消费者长期个人面板，不提供同一真人的长期消费标签 |
| [UCI Restaurant & consumer data](https://archive.ics.uci.edu/dataset/232/restaurant%2Bconsumer%2Bdata) | 小规模画像/菜系偏好/餐厅属性与评分基线；检查个性化是否有增益 | 138 个用户画像、130 家餐厅、1,161 条评分；价格/预算为 low/medium/high 档，不能显示为真实人民币。缺少完整多轮历史、曝光集合及可靠时间序列；评分不是实际支付或互斥选择标签 |
| 本项目经授权采集的匿名纵向数据 | 核心个体孪生验证：初始化访谈、多次消费情境、截至时点的对话、实际选择、满意度与拒绝原因 | 对目标人群和地域负责；问卷自述/情境选择/真实下单分开。需要匿名 ID、数据撤回与留出协议，不能把网页演示交互当真人实证 |

建议起步组合：**LifeSim + MultiWOZ 餐厅域 + UCI 小基线 + 自采用户面板**。暂不围绕 TaobaoAd 训练点击模型，也不拼接这些数据集的用户身份。公开数据用于不同子任务，自采面板承担主要外部验证。未评分/未曝光的餐厅不能直接当作明确拒绝。

MultiWOZ 保留官方 train/dev/test，过滤餐厅域时保存原对话 ID；同一完整对话不拆到不同集合。UCI 没有可信时序时不能伪造时间划分；采用用户级划分检验新用户泛化，或在明确标注局限的已观测评分集合中做留出评分/排序任务。不要凭空补出用户从未看到的竞争候选。

## 5. 评测分三层

| 层次 | 可回答的问题 | 建议指标与证据 |
|---|---|---|
| A. 对话助手 | 是否正确识别并满足明确/隐含需求，能否持续记住偏好？ | 按 LifeSim 意图清单逐项标注识别率和完成率，分显式/隐式报告；已知维度偏好恢复准确率、未知属性臆造率；自然度、连贯性和人格对齐按原量表，另报硬条件违规率和新条件适应失败率 |
| B. 消费者孪生 | 是否像指定用户行动？是否预测真人的留出选择？ | 先评模拟用户意图/画像/情境一致性与自然度；再在人类留出任务上报 Top-1、MRR/Recall@k，按用户平均；有合法选择概率才报 LogLoss、Brier 和校准。满意度预测另报 MAE；不同标签不混算 |
| C. 场景与干预 | 对环境变化的反应是否可解释、稳健且可复现？ | 成对分支保持相同用户/历史/候选，报告选择变化、外部选项比例、重复运行方差和群体差异；如果有真实干预，单独检验真实效果和模拟效果差距，否则只称模拟敏感性 |

硬条件由程序检查，LLM 评审只处理需要语义判断的部分。评审模型与消费者/助手模型尽量分离，隐藏系统身份并随机呈现样本；抽取双人或多人盲评样本，报告一致性，不能由同一个模型同时生成“真值”并给自己判分。检查评审与人评相关性及偏差。

LLM-as-Judge、“像真人”的语言和高用户满意度，均不能替代真实行为一致性。LifeSim 的助手意图完成率也不能替代消费者选择预测指标。

## 6. 可执行的首轮实验设计（建议，非论文原设定）

先做约 20–30 名目标用户的流程试点，每人 6–10 个餐饮情境，用于发现提问、标签和记录问题，不据此宣称代表总体。正式样本量依据试点方差、主要效应大小和预先指定指标做功效分析。

对每名用户，将前期访谈/情境用于个性化建立，后期未见情境用于测试；跨用户泛化再设置整用户留出。提示词、模型选择和阈值只用开发用户调试。测试标签只供评测器访问，禁止回写到测试前的检索记忆。相同情境改变展示顺序，并控制同一人的重复任务及顺序效应。

固定候选与推理预算，比较：

- B0：只用情境的无个性化代理。
- B1：只用初始问卷画像。
- B2：画像 + 简单近期对话/记忆。
- B3：LifeSim 原生画像与记忆 + 新增消费选择模块。
- 消融：无追问、无长期记忆、无个体画像；另单独比较规则动作基线。

主指标建议先定为真实留出情境的 Top-1 选择一致率（包含“不消费”）；辅助报告显/隐意图完成、画像恢复、硬条件违规和对话成本。按用户而非逐条消息做配对比较和 bootstrap 置信区间，重复随机种子；不要只挑好看的个案。公布失败场景，如偏好冲突、预算不足、无候选、用户拒绝和长历史遗忘。

## 7. 最小研究记录格式

`study_id, participant_id, episode_id, branch_id, parent_snapshot_id, mode, source, timestamp, profile_version, history_cutoff, turns[], candidate_set[], display_order[], context, evidence[], prediction, prediction_frozen_at, human_choice, human_choice_source, satisfaction, model_version, prompt_version, code_version, seed, evaluator_version`。

`mode` 至少区分 `elicitation`、`assistant`、`twin_simulation`；`source` 区分真人、公开日志、LLM 合成与规则 demo。`human_choice` 在独立反馈前为 null，缺失不是负例。预测后发生的 feedback 不能倒灌入冻结快照。

当前网页已接入LifeSim原生多轮代理、DeepSeek和硅基流动语义记忆，支持事实确认、持久会话、基线快照/条件分支、服务端封存预测和独立情境选择。模型预演来源为 `lifesim_deepseek_simulation`，规则模式另标 `rule_based_demo`；集成脚本记录标为 `integration_probe`，不能当成人类实验样本。正式参与者研究、随机任务分配及批量论文评测仍待实施，联通验证不是行为预测有效性的实证结论。

## 8. 实施顺序

1. 确认研究问题、首个餐饮任务和主指标；把网页改成多轮研究工作台。
2. 在现有后端增加持久多轮会话、原生用户代理动作、情境快照/分支及可重放轨迹，而非重新做独立个性化框架。
3. 复现 LifeSim 协议与餐饮子集，用 MultiWOZ 检查状态跟踪，以 UCI 验证偏好基线；保持数据来源独立。
4. 试点采集真人纵向数据，冻结预测后收集独立选择，比较上述基线与消融。
5. 在个体有效性验证后研究券干预和人群扩展，报告外部效度边界。
